Section 1 • Mindset

Debugging philosophy: don't randomly try commands

Every CAP bug follows the same operating loop. Memorize it before touching the keyboard.

flowchart TD
A[SYMPTOM] --> B[REPRODUCE THE BUG]
B --> C[IDENTIFY THE LAYER]
C --> D[COLLECT EVIDENCE]
D --> E[ISOLATE THE COMPONENT]
E --> F[CHECK LOGS / CONFIG / REQUEST]
F --> G[ROOT CAUSE]
G --> H[FIX]
H --> I[RETEST + VERIFY]
SymptomWhat you SEE. UI5 shows "Request failed". This is never the diagnosis.
CauseWhat directly broke. OData returned 500.
Root causeWhy it broke. Handler used wrong property Books.stockCount.
Real example — bookshop: Fiori shows "Request failed" on /bahi. Network tab says 500. CAP terminal says Cannot read properties of undefined (reading 'stock') in catalog-service.js:18. Root cause: req.params[0] is undefined for unbound call. Fix: separate bound vs unbound handler. Verify: Invoke-RestMethod .../bahi returns 200.
Golden distinction: FIX changes code/config. VERIFICATION proves it with a repeated command + output. No verification = no fix.
Beginner trap: editing 3 files at once. Change one thing, retest, then continue. Otherwise you never learn what worked.
  • I can recite the 9-step loop without looking
  • I can separate symptom / cause / root cause / fix / verification for one past bug

Section 4 • PowerShell

PowerShell fundamentals for CAP debugging

All commands run in Windows PowerShell 5.1 / 7 from your project root E:\...\bookshop. Linux-style DEBUG=sql cds watch never works here — see Section 9.

Get-Location — where am I?

Why: wrong folder = wrong package.json / model. When: first command in any session.
Get-Location
# expect: ...\CAP_PRACTICE\bookshop
# bug sign: path ends in CAP_PRACTICE (one level up) -> cds finds no model
# fix: Set-Location .\bookshop  | verify: Get-ChildItem package.json

Get-ChildItem / Get-Content / Select-String — inspect without opening an editor

Get-ChildItem
Get-ChildItem .\mta_archives\
Get-Content package.json
Get-Content .\.cdsrc.json
Select-String -Path "srv\*.js" -Pattern "removeStock|applyDiscount"
# bug sign: Select-String finds handler name in .cds but NOT in .js -> unimplemented action (500)

Get-NetTCPConnection + Get-Process — port 4004 busy?

Get-NetTCPConnection -LocalPort 4004 | Select-Object OwningProcess, State
Get-Process -Id <PID>
Stop-Process -Id <PID>   # last resort; prefer Ctrl+C in the right terminal
# bug sign: EADDRINUSE / server exits instantly -> old cds watch still running

Invoke-WebRequest vs Invoke-RestMethod — test OData without a browser

Invoke-WebRequest "http://localhost:4004/odata/v4/catalog/$metadata" | Select-Object StatusCode
Invoke-RestMethod "http://localhost:4004/odata/v4/catalog/bahi?$top=2"
# WebRequest = raw HTTP (headers/status); RestMethod = parsed JSON. Use RestMethod for data, WebRequest for status/headers.
  • I run Get-Location before every debug session
  • I can free port 4004 and test $metadata from PowerShell

# bug signs: ERESOLVE / Cannot find module @sap/cds -> npm install needed

Section 6 • CAP runtime

cds watch masterclass

flowchart TD
W[cds watch] --> L[Load CDS] --> C[Compile model] --> S[Load services] --> D[Init DB] --> H[HTTP server] --> OK[localhost:4004]

npx cds watch — full diagnostic

What: dev server with file watching + auto restart. Why: single fastest evidence source. Where: project root (where package.json sits). When: always first for local bugs.
Set-Location "E:\SAP PROJECTS\SameerbhaiProject\CAP_PRACTICE\bookshop"
npx cds watch
# EXPECT: [cds] serving CatalogService { path: '/odata/v4/catalog' } ... server listening on { url: 'http://localhost:4004' }
# Open: http://localhost:4004  and  http://localhost:4004/odata/v4/catalog/$metadata
# BUG SIGNS + NEXT:
#  EADDRINUSE -> Get-NetTCPConnection -LocalPort 4004 (Sec 4)
#  "Cannot find module" -> npm install (Sec 5)
#  CDS compile error with file:line -> npx cds compile "*" (Sec 10)
#  "Failed to connect database" -> cds env get requires.db (Sec 8)
# FIX: fix FIRST error only, save, watch restarts. VERIFY: endpoints return 200.
Starts OK: you see server listening. If an endpoint then fails, the bug is in service/handler/CQL — go to Sec 13/14.
Fails at startup: scroll to the first error, ignore the cascade below it. The first error is the cause, the rest are symptoms.
watch shows nothing at localhost:4004? Beginner

Check: terminal still running? Correct folder (Get-Location)? Port busy? Firewall? Try npx cds serve as a control — if serve works but watch doesn't, the watcher itself is broken (rare), not your app.

How do I know if it is startup vs endpoint vs DB failure? Developer

Startup: no listening line. Endpoint: listening OK, URL returns 404/500. DB: endpoint works for metadata but entity reads fail with SQL errors — enable $env:DEBUG="sql".

  • I can start watch and open /$metadata successfully

Section 9 • Logging

DEBUG variables — the PowerShell fix (your exact error)

Your error: DEBUG=sql : The term 'DEBUG=sql' is not recognized... — that is Linux/macOS syntax. PowerShell sets env vars with $env:. Never prefix the command.

Correct PowerShell syntax

$env:DEBUG="cds*"; npx cds watch
$env:DEBUG="sql"; npx cds watch
$env:DEBUG="remote"; npx cds watch
$env:DEBUG="cds*,sql,remote"; npx cds watch
$env:DEBUG                        # check current value
Remove-Item Env:\DEBUG             # reset to quiet
# one-liner that auto-cleans (PowerShell 7):
& { $env:DEBUG="sql"; npx cds watch }

Accuracy note: namespaces vary by CAP/runtime version. Verify with npx cds --version + npx cds help and current CAP docs. Prefer cds*, sql, remote — valid on current releases.

Section 12 • Queries

CQL debugging + CQL vs SQL

CQL (what you write)
SELECT.from(Books)
SELECT.from(Books).where({stock:{'>':10}})
UPDATE(Books).set({stock:{'+=':5}}).where({ID})
INSERT.into(Books).entries({...})
DELETE.from(Books).where({stock:0})
SQL (what the DB runs)
SELECT * FROM Books
SELECT * FROM Books WHERE stock > 10
UPDATE Books SET stock = stock + 5 WHERE ID=?
INSERT INTO Books (...) VALUES (...)
DELETE FROM Books WHERE stock=0
flowchart LR
CQL[CQL in handler] --> ENG[CAP query engine] --> SQL[SQL] --> DB2[(Database)]

Section 13 • API

OData masterclass + PowerShell API testing + status codes

Metadata → entity → function → action (in this order)

Invoke-WebRequest "http://localhost:4004/odata/v4/catalog/$metadata" | Select-Object StatusCode
Invoke-RestMethod "http://localhost:4004/odata/v4/catalog/bahi?$top=2"
Invoke-RestMethod "http://localhost:4004/odata/v4/catalog/totalStock()"
Invoke-RestMethod "http://localhost:4004/odata/v4/catalog/booksByPriceRange(min=10,max=13)"
$body = @{ amount = 10 } | ConvertTo-Json
Invoke-RestMethod -Uri "http://localhost:4004/odata/v4/catalog/bahi(201)/addStock" -Method POST -ContentType "application/json" -Body $body
# Every line: Uri = endpoint; Method = GET/POST/PATCH/DELETE; ContentType = json for writes; Body = ConvertTo-Json hashtable.

GET / POST / PATCH / DELETE + headers + auth (copy-paste)

# GET with query
Invoke-RestMethod "http://localhost:4004/odata/v4/catalog/bahi?$select=ID,title,stock&$top=5"
# PATCH stock of one book
$patch = @{ stock = 25 } | ConvertTo-Json
Invoke-RestMethod -Uri "http://localhost:4004/odata/v4/catalog/bahi(201)" -Method PATCH -ContentType "application/json" -Body $patch
# DELETE one book
Invoke-RestMethod -Uri "http://localhost:4004/odata/v4/catalog/bahi(201)" -Method DELETE
# Custom header (e.g. correlation ID) + bearer token (hybrid/CF)
$headers = @{ "Authorization" = "Bearer <TOKEN>"; "X-Correlation-ID" = "debug-001" }
Invoke-RestMethod -Uri "http://localhost:4004/odata/v4/catalog/bahi" -Headers $headers
# Raw status + headers view (use WebRequest, not RestMethod)
$r = Invoke-WebRequest "http://localhost:4004/odata/v4/catalog/bahi(201)" -Method GET
$r.StatusCode; $r.Headers["Content-Type"]
Status-code triage drills Developer

400: log shows validation message → fix URL/body. 404: compare URL vs $metadata. 405: action called with GET → switch to POST. 409: duplicate key/ETag → GET current row first. 500: terminal stack trace names handler file:line → fix code. 502/503: remote/CF down → Sec 16/18. Click any decision button in Sec 20 for the sequence.
